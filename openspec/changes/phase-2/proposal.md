# Proposal: 二期需求（晚市 / 石头剪刀布协商 / 订阅消息）

## Why

MVP 仅覆盖工作日午饭 + 手动/主动带两种约定来源，推送仅系统内红点。一期联调自测（itest 50/50）已闭环，二期补齐三块明确拍板过的能力：

1. **晚市**：情侣晚饭同样需要"约谁带、带啥"。MVP 阶段已拍板"午+晚二期"。
2. **石头剪刀布协商**：把"今天谁带"的扯皮变成有趣的迷你对局，输家带饭。
3. **微信订阅消息**：关键节点（被认领 / 已交付 / 待打卡）用订阅消息主动提醒，替代纯红点。

## What Changes

- 新增能力 `meal-type-evening`：`meal_type` 支持 `2=晚饭`，按餐段配置发起截止时间，状态机 / 超时流转 / 打卡窗口适配。
- 新增能力 `rps-negotiation`：石头剪刀布对局，决定带饭方，可一键采纳生成主动带约定（source=1）。
- 新增能力 `subscribe-message`：接入微信订阅消息下发，关键事件触发，无模板 / 无授权优雅跳过。

## Impact

- 数据模型：`meal_plan.meal_type` 语义扩展（已是 int，无需改列）；新增 `rps_game` / `rps_round` 表。
- 受影响现有能力：`meal-plan`（餐段扩展）、`notifications`（新增订阅消息通道）。
- 前端：创建约定增加餐段选择；新增石头剪刀布页；订阅消息授权触发点。
- 不在本期：晚市周末自动排班（仍手动）、订阅消息模板在微信后台的注册（需用户操作 MP 控制台）。
