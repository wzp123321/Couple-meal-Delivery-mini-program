# 80 采购清单 · 前端

> **OpenSpec**：`shopping-list` · **里程碑** M5
> **页面**：`pages/shopping`（入口在 `pages/plan-detail` 内）
> **前置必读**：`../00-全局约定.md`、`../前端-00-基础设施.md`
> **接口契约**：见 `后端.md §2`
> **后端对应**：`后端.md`

---

## 1. 页面 → 接口

| 位置 | 调用 | 时机 |
|---|---|---|
| `plan-detail` | `POST /api/shopping/generate` | 点「生成采购清单」，成功后跳转采购页 |
| `shopping` | `GET /api/shopping/list` | 进页 / 从详情页带 `planId` 进入 |
| `shopping` | `POST /api/shopping/check` | 勾选 / 取消勾选 |

---

## 2. 采购页（`pages/shopping`）

| 区域 | 要点 |
|---|---|
| 顶部 | 关联约定卡片（日期 + 菜品），说明这是「为这顿饭要买的东西」 |
| 未买区 | 复选框列表，勾选即调 `/check`，**本地立即翻转再异步提交**（此处是唯一允许乐观更新的地方，因为操作可逆） |
| 已买区 | 置底折叠，灰字，可取消勾选拉回未买区 |
| 空态 | `empty-state`「还没有清单，从约定详情里生成一份」 |
| 进度 | 顶部「已买 3/8」进度条 |

---

## 3. 入口

只在 `pages/plan-detail` 内提供「生成采购清单」按钮，`status ∈ {1,2,3}` 时可见。
生成成功后直接跳转采购页。

---

## 4. 验收要点

对照 `openspec/changes/bootstrap-mvp/specs/shopping-list/spec.md`：

- [ ] 详情页在 `status` 为 1/2/3 时显示生成入口，终态不显示
- [ ] 重复点「生成」不会在清单里出现重复条目
- [ ] 勾选即时翻转，接口失败时回滚并提示
- [ ] 取消勾选后条目回到未买区，进度条同步减少
- [ ] 已买区默认折叠，展开后置底展示

---

## 5. 易错点

| 坑 | 说明 |
|---|---|
| 勾选也走"重取全部" | 这个操作**可逆且高频**，是全项目唯一允许乐观更新的地方：本地立即翻转 + 异步提交 |
| 乐观更新失败不回滚 | 会把界面留在错误状态。失败必须翻回去并轻提示 |
| 已买条目隐藏 | 用户想核对买了什么就没了。**置底折叠 + 灰字** |
| 生成入口对所有状态可见 | 终态（4/5/6）点了必然 1004，属无效交互 |
