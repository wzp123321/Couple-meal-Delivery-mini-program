## 1. 数据表

### `shopping_list`

| 字段 | 类型 | 说明 |
|---|---|---|
| `plan_id` | BIGINT | 关联约定 |
| `couple_id` | BIGINT | 关系隔离键 |
| `item_name` | VARCHAR(128) | 食材 / 商品名 |
| `checked_flag` | TINYINT | `0` 未买 / `1` 已买 |
| `checked_time` | DATETIME NULL | 勾选时间 |
| `seq` | TINYINT | 排序 |

**两条索引**：

| 索引 | 作用 |
|---|---|
| `uk_shopping_list_plan_item(plan_id, item_name)` | **重复生成不产生重复条目** —— 幂等核心 |
| `idx_shopping_list_couple_checked(couple_id, checked_flag)` | 未买清单查询 |

## 2. 接口契约

| 方法 | 路径 | 入参 | 出参 | 错误码 |
|---|---|---|---|---|
| POST | `/api/shopping/generate` | `planId`, `items[]?`（不传则由约定菜品推导） | 生成后的清单 | 1002, 1004 |
| GET | `/api/shopping/list` | `planId?`（不传取最近未买） | `list[]` | 1002 |
| POST | `/api/shopping/check` | `id`, `checked_flag` | — | 1002 |

## 3. 实现

### 3.1 生成（幂等）

```
POST /api/shopping/generate { planId, items[]? }
```

1. 校验 `plan.coupleId == ctx.coupleId`，否则 `1002`。
2. 校验 `status ∈ {0,1,2,3}`（终态不再生成），否则 `1004`。
3. 条目来源：显式传 `items` 则用之；否则由 `meal_plan_item` 的菜名推导（MVP 简化：一菜一条，名称为「{菜名} 的食材」可留待人工改）。
4. **逐条 insert，靠 `uk_shopping_list_plan_item` 防重**，冲突即忽略：

```java
for (String name : names) {
    try {
        shoppingMapper.insert(planId, coupleId, name, seq++);
    } catch (DuplicateKeyException e) {
        // 已存在，跳过
    }
}
```

> 不要"先 count 再 insert"，并发点两次会翻倍（见 `../01-通用机制.md §2` 原则 1）。

### 3.2 勾选

```sql
UPDATE shopping_list
SET checked_flag = ?, checked_time = IF(? = 1, NOW(), NULL)
WHERE id = ? AND couple_id = ?
```

- **幂等**：同一个值重复勾选无副作用。
- 支持取消勾选（`checked_flag=0` 时 `checked_time` 置回 NULL）。

### 3.3 查询

- 传 `planId` → 该约定的清单。
- 不传 → 最近一条有未买条目的清单（`checked_flag=0`，走 `idx_shopping_list_couple_checked`）。
- 已买条目**保留展示**（由前端置底、灰色），不做删除。

## 5. 验收要点

对照 `openspec/changes/bootstrap-mvp/specs/shopping-list/spec.md`：

- [ ] 同一约定重复生成，条目数不翻倍
- [ ] 并发点两次「生成」，条目数仍不翻倍
- [ ] 勾选后可取消勾选，`checked_time` 对应置空
- [ ] 跨关系访问他人在清单返回 1002
- [ ] 终态（4/5/6）约定不能再生成，返回 1004

## 6. 易错点

| 坑 | 说明 |
|---|---|
| 生成前先 `count` 判重 | 并发下条目翻倍。**靠 `uk_shopping_list_plan_item` + catch** |
| 已买条目直接删掉 | 用户想核对买了什么就没了。**保留，由前端置底展示** |
| `checked_time` 不置空 | 取消勾选后时间还留着，排序会错乱 |
| 查询不带 `couple_id` | 只按 `id` 更新会越权改到别人清单 |
