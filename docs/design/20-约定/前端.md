# 20 约定（核心模块） · 前端

> **OpenSpec**：`meal-plan` · **里程碑** M2（最关键）
> **页面**：`pages/today` `pages/plan-create` `pages/plan-detail`
> **前置必读**：`../00-全局约定.md`、`../前端-00-基础设施.md`、`../01-通用机制.md`（状态语义）
> **接口契约**：见 `后端.md §2`（入参/出参与错误码**只在那里定义**）
> **后端对应**：`后端.md`

---

## 1. 页面 → 接口

| 页面 | 调用 | 时机 |
|---|---|---|
| `today` | `GET /api/plan/today` | 进入 / 下拉刷新 / 任一动作返回后 |
| `plan-create` | `POST /api/plan/create` | 提交（命中忌口时二次确认后仍提交） |
| `plan-detail` | `GET /api/plan/{id}` | 进入 / **每个动作成功后重新拉取** |
| `plan-detail` | `POST /api/plan/{id}/…`（动作接口） | 点对应按钮 |

> 动作接口的 8 个 endpoint（claim / withdraw / confirm / reject / deliver / complete / cancel / reassign）见 `后端.md §2`；路径拼接统一由 `api/plan.ts` 收敛，页面不手写 URL。

---

## 2. 发起约定

```
选菜（菜单选择层，多选带回）
  → 命中 avoid_level ≥ 2 的菜
  → 提交前拦截，弹 L3 强提醒：「TA 不吃香菜哦，还要点吗？」
  → 用户确认 → 照常提交（后端只回 warnings，不硬拦）
```

- 草稿：`onHide` / 提交失败时写 `storage['draft:plan-create']`，`onLoad` 时回填并提示
  「上次有没发出去的，继续吗？」
- 18:00 后发起当日：前端直接禁用「今天」选项并显示文案，不靠后端 1010 兜底（但后端仍校验）。
- 日期选择只给 `[today, today+7]` 内的工作日，周末置灰。

---

## 3. 动作后的刷新

每个动作成功后**不做本地乐观更新**，统一重新 `GET /api/plan/{id}`：

| 动作 | 成功提示 | 之后 |
|---|---|---|
| claim | 「接下来交给你啦」 | 重取详情 + 通知对方红点 +1 |
| deliver | 「已标记送达」 | 重取详情 |
| complete | 「这顿饭完成啦」 | 重取详情 + 刷新爱心值 |
| cancel | 「已经取消」 | 返回今日页并刷新列表 |
| reject | 文案比"取消"柔和（PRD §12.11） | 返回今日页并刷新列表 |

## 4. 按钮显隐

**优先读后端返回的 `actions[]`**；仅在离线兜底时按 PRD §12.4 本地推算：

```js
const can = {
  claim:     p.status === 0 && p.ordererId !== me,
  withdraw:  p.status === 2 && p.carrierId === me,   // 认领一步到位后撤回起点是 2
  confirm:   p.status === 1 && p.ordererId === me,
  deliver:   p.status === 2 && p.carrierId === me,
  complete:  p.status === 3 && p.ordererId === me,
  checkin:   [3, 4].includes(p.status) && p.ordererId === me,
  cancel:    [0,1,2,3].includes(p.status)
};
```

> **前端只做显隐，不做授权。** 后端状态机会再校验一次，前端隐藏不能替代后端拒绝。

---

## 5. 验收要点

对照 `openspec/changes/bootstrap-mvp/specs/meal-plan/spec.md`：

- [ ] 18:00 后「今天」选项即时禁用，页面无需等接口返回
- [ ] 日期选择器只列 7 天内工作日，周末不可选
- [ ] 命中 `avoid_level ≥ 2` 的菜弹出 L3 强提醒，取消则停留、确认则照常提交
- [ ] 提交失败或中途退出，再次进入能提示并恢复草稿
- [ ] 任一动作成功后详情页数据来自重新拉取，不是本地改的
- [ ] 按钮集合与 `actions[]` 完全一致；离线兜底推算结果与之一致
- [ ] 取消必须填原因，未填时提交按钮不可点

---

## 6. 易错点

| 坑 | 说明 |
|---|---|
| 前端自己推按钮显隐 | 应优先用后端 `actions[]`，否则权限矩阵改一处要改两端 |
| 动作后本地乐观更新 | 状态机可能拒绝，界面会走到和后端不一致的状态。**统一重取** |
| `withdraw` 按 `status===1` 判显隐 | 认领已一步进 `2`，这里的起点是 `2`。写错会导致「撤回」按钮永不出现 |
| 忌口在前端硬拦 | 产品要求"只提醒不硬拦"，拦死等于改了规则 |
| 草稿不清 | 提交成功后必须清 `draft:plan-create`，否则下次进页反复提示恢复 |
