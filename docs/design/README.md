# 设计文档导航

> 本目录按**需求（业务模块）纵向切分**：一个需求一个目录，目录内**前端、后端各一份文档**。
> **目的**：做某个功能的代码时，后端只读「全局约定 + 该模块后端」，前端只读「前端基础设施 + 该模块前端」——
> 单人单端约 200–350 行，不会一次性灌入上千行设计导致代码生成走偏。

---

## 阅读纪律（硬规则）

1. **一次只读一个模块的一份文档**。做后端就读 `后端.md`，做前端就读 `前端.md`，不要两份一起读。
2. 顺序永远是：**本文档 → 按任务查表 → 只打开列出的文件**。
3. 模块文档之间**不互相包含**，只通过显式指针引用：模块文档里写 `../01-通用机制.md §1`，本文档内引用写 `01-通用机制.md §1`。
4. **接口契约只定义在 `后端.md §2`**；`前端.md` 只写「页面 → 接口」映射，不重复入参出参。
5. 模块文档与 `../../db/schema.sql` 冲突时，**以 `schema.sql` 为准**。
6. 模块文档与 PRD 冲突时，以 `00-全局约定.md` 的「设计决策」为准，其余以 PRD 为准。

## 文档写法约定

- 后端文档固定顺序：数据表 → 接口契约 → 实现 → 定时任务 → 验收要点 → 易错点。
- 前端文档固定顺序：页面→接口 → 主要交互 → 状态与缓存 → 验收要点 → 易错点。
- 验收要点分前后端各写各的：后端写接口/数据/Job 可断言的结果，前端写可点的交互结果。

**开发顺序**：M0（骨架 + 建库 + 登录）→ M1（绑定 + 账户）→ M2（约定闭环，最关键）→ M3（菜单）→
M4（爱心值 + 通知）→ M5（历史 / 采购 / 周历）→ M5.5（打卡 + 审核）→ M6（超时与调度）→ M7（验收上线）。
与 `openspec/changes/bootstrap-mvp/tasks.md` 的 9 个任务组一一对应。
