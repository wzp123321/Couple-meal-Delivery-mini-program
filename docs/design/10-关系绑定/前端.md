## 1. 页面 → 接口

| 页面 | 调用 | 时机 |
|---|---|---|
| `login` | `POST /api/auth/login` | 勾选协议后点登录 |
| `pair` | `POST /api/couple/invite` / `POST /api/couple/join` | 生成码 / 输满 6 位自动提交 |
| 全局（冷启动） | `GET /api/couple/info` | `onLaunch` 静默恢复，判别有无关系 |
| `me` | `GET /api/couple/info` + `GET /api/msg/unread` | 切到 Tab4 时刷新关系卡片与未读角标 |
| `settings` | `POST /api/couple/settings`·`/unbind`·`/api/user/delete` | 保存 / 解绑 / 注销 |

> 所有请求统一走 `utils/request.ts`，各页面不写 `uni.request`。

## 2. 冷启动与登录门控

```
app.onLaunch
  ├─ 从 storage 读 token
  ├─ 有 → 静默恢复：GET /api/couple/info
  │        ├─ 有 relation → 进 tabBar 首页
  │        └─ 1002 → 进配对页
  └─ 无 → 进登录页
```

- 登录页：`<button open-type="getUserInfo">` 已不可用，改用**隐私协议弹窗 + 普通按钮**触发 `uni.login`，
  未勾选协议不调接口（PRD §5.1）。
- 头像昵称在「设置」页用 `<button open-type="chooseAvatar">` + `<input type="nickname">` 更新，登录时不强制填。
  这两项是微信专有能力，需条件编译包住，见 `../前端-00-基础设施.md §2`。
- 页面级门控由 `utils/guard.ts` 的全局路由拦截统一处理（`uni.addInterceptor`），页面不各写一遍。

## 3. 页面要点

| 页面 | 要点 |
|---|---|
| `login` | 协议未勾选时按钮置灰，不发请求；登录成功写 storage + `setState({user})` |
| `pair` | 双 Tab：生成码（倒计时 24h、可复制）/ 输入码（6 位数字键盘，输满自动提交） |
| `me` | 顶部关系卡片（双人头像、称呼、在一起天数、累计爱心值，数据来自 `couple/info`）；下方五个入口：共同周历 `weekly` / 月度轻报告（`history` 内弹层）/ 饭桌相册 `gallery` / 历史 `history` / 设置 `settings`。**只是入口聚合页，自身不发业务请求** |
| `settings` | 称呼、纪念日、主题、提醒开关；解绑与注销均需二次确认弹层（L3 级别强提醒），注销额外要求勾选知晓项 |

**注销交互**：弹层必须勾选「我已知晓：注销后无法恢复，我上传的打卡照片会被删除」才放行；成功后清 storage 并 `reLaunch` 到登录页。

---

## 4. 缓存与状态

**解绑必须清缓存**：清 storage 中 `draft:*` 与登录态以外的键，`setState({relation: null})`，
否则换绑后旧关系信息仍在内存里。

**注销必须全清**：token、`user`、`relation`、所有 `draft:*` 一并清空，避免下一个登录者看到上一个人的残影。

## 5. 验收要点

对照 `openspec/changes/bootstrap-mvp/specs/couple-binding/spec.md`：

- [ ] 未勾选隐私协议时登录按钮置灰，点击不发请求
- [ ] 冷启动有 token 且已有关系 → 直接进首页，不闪登录页
- [ ] 冷启动有 token 但已解绑 → 落到配对页，不报错弹窗
- [ ] 邀请码倒计时按 `expireAt` 计算，过期后按钮变「重新生成」
- [ ] 输入码填满 6 位自动提交，不必再点按钮
- [ ] 解绑 / 注销二次确认弹层为 L3 强提醒，注销需勾选知晓项
- [ ] 注销成功后 storage 无残留，`reLaunch` 到登录页

## 6. 易错点

| 坑 | 说明 |
|---|---|
| 解绑只改状态不清缓存 | 前端仍显示旧关系，用户以为没解绑成功 |
| 门控逻辑写进每个页面 | 页面一多必然漏。**统一放 `utils/guard.ts`** |
| 用 `getUserProfile` 拿头像昵称 | 该能力已废弃，必须换 `chooseAvatar` + `type="nickname"`，且需真机验证 |
| 注销后只清 token | `user` / `relation` 残留会让配对页显示上一个账号的信息 |
