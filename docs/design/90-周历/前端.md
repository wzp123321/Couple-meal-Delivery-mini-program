## 2. 周历页（`pages/weekly`）

| 区域 | 要点 |
|---|---|
| 顶部 | 「本周」+ 左右切换箭头 + 回到本周 |
| 主体 | 7 行（周一至周五正常，周末灰底标「休息日」） |
| 每行 | 左侧日期 + 星期；右侧约定卡片（`plan-card` 精简版）或「还没约」 |
| 今天 | 整行高亮（暖橘左竖条） |
| 空行点击 | 若该日是工作日且未过期 → 跳到发起页并带上 `planDate` |

## 3. 二期：协商谁带（不实现）

设计意向（PRD 突出点 D）：

- 同一约定下双方各自出「石头/剪刀/布」，都出完后公布结果，赢的人带饭。
- 数据落 `meal_plan` 的新字段或独立表，需在二期重新评估表结构。
- 无论结果如何，**最终仍由人来点「认领」**，不自动改 `carrier_id`，避免"被安排"。

> 原型里的协商弹层已标「二期预览」，MVP 不接入口。

---

## 4. 验收要点

对照 `openspec/changes/bootstrap-mvp/specs/weekly-schedule/spec.md`：

- [ ] 固定 7 行，没有约定的日子显示「还没约」而不是留白
- [ ] 周六周日灰底标「休息日」，不可点进发起页
- [ ] 今天整行高亮
- [ ] 左右切换按整周跳，超出 ±4 周后箭头置灰
- [ ] 点空行跳到发起页且日期已预填
- [ ] 页面无任何状态操作按钮（操作一律去详情页）

---

## 5. 易错点

| 坑 | 说明 |
|---|---|
| 只渲染有约定的天 | 布局会塌，必须画满 7 行 |
| 空行去掉「还没约」占位 | 用户不知道这天可以约，失去入口 |
| 周末也能点进发起页 | 后端会返回 1009，属无效交互。前端直接禁用 |
| 在周历里放操作按钮 | 会与详情页形成两套状态判定逻辑，必然分叉 |
| 协商入口提前接上 | 二期功能，MVP 接了就是半成品 |
