# 90 周历 · 后端

> **OpenSpec**：`weekly-schedule` · **里程碑** M5
> **Service**：`PlanService`（复用） · **表**：`meal_plan`（**只读**）
> **前置必读**：`../00-全局约定.md`、`../01-通用机制.md`（状态语义）、`../后端-00-架构.md`
> **前端对应**：`前端.md`

> ⚠️ **范围**：本模块只做**只读周历视图**。协商（石头剪刀布）由 `rps-negotiation` 独立实现（`rps_game` / `rps_round`），周历不承载其数据与入口。

## 1. 数据表

**不拥有自己的表**，只读 `meal_plan`，走 `idx_meal_plan_couple_date(couple_id, plan_date, status)`。

> 与 `../70-历史/后端.md` 的区别：历史看**过去的终态**，周历看**本周的排期**（含今天及未来）。

---

## 2. 接口契约

| 方法 | 路径 | 入参 | 出参 | 错误码 |
|---|---|---|---|---|
| GET | `/api/plan/week` | `startDate?`（默认本周一） | 7 天数组，每天含约定列表 | 1002 |

出参结构：

```json
{
  "weekStart": "2026-10-26",
  "days": [
    {
      "date": "2026-10-26",
      "weekday": 1,
      "isWorkday": true,
      "isToday": true,
      "plans": [
        { "id": 12, "status": 2, "role": "orderer", "items": ["番茄炒蛋"] }
      ]
    }
  ]
}
```

> **即使某天没有约定，也要占位返回**（`plans: []`），前端才能画满 7 格。

---

## 3. 实现

### 3.1 查询

```sql
SELECT p.id, p.plan_date, p.status, p.orderer_id, p.carrier_id
FROM meal_plan p
WHERE p.couple_id = #{ctx.coupleId}
  AND p.plan_date BETWEEN #{weekStart} AND #{weekStart + 6 天}
ORDER BY p.plan_date, p.id;
```

- 一次查询取全周，**在内存里按 `plan_date` 分组**，逐天查会 7 次往返。
- 菜品名走一次 `meal_plan_item` 的 `IN` 批量查询，再按 `plan_id` 归组。
- `weekday` 由日期计算，`isWorkday` 用 `WorkdayUtil`（周一至周五）。

### 3.2 参数边界

- `startDate` 缺省取**本周周一**（含今天所在周）。
- 允许往前翻（看上周）和往后翻（看下周），**限定 ±4 周**，超范围返回空周而非报错。

## 5. 验收要点

对照 `openspec/changes/bootstrap-mvp/specs/weekly-schedule/spec.md`：

- [ ] 返回固定 7 天，无约定的日子 `plans: []` 占位
- [ ] `isWorkday` 周六日为 false
- [ ] `isToday` 只有当天为 true
- [ ] 一次请求完成，不产生 N+1
- [ ] 只看得到本关系的约定（跨关系返回空）
- [ ] 超出 ±4 周返回空周，不报错

---

## 6. 易错点

| 坑 | 说明 |
|---|---|
| 只返回有约定的天 | 前端画不满 7 格，布局会塌 |
| 逐天查询 | 7 次往返。**一次查全周再内存分组** |
| 菜品名逐条查 | 同样会造成 N+1，必须批量 `IN` |
| 周历里做状态操作 | MVP 是只读视图，操作一律去详情页，避免两处状态判定逻辑分叉 |
