## 1. 数据表

### `love_value`（流水表，不是余额表）

| 字段 | 类型 | 说明 |
|---|---|---|
| `couple_id` | BIGINT | 关系隔离键 |
| `user_id` | BIGINT | **获得方**（carrier，带饭的人） |
| `plan_id` | BIGINT NULL | 来源约定；`NULL` 表示非约定来源（预留） |
| `delta` | INT | 增量，正数 |
| `reason` | VARCHAR(64) | 如「带饭完成」 |

**两条索引，各司其职**：

| 索引 | 作用 |
|---|---|
| `uk_love_value_plan_user(plan_id, user_id)` | **幂等核心** —— 同一约定对同一人只可能加一次，重复插入由数据库拒绝（D7） |
| `idx_love_value_couple_user(couple_id, user_id)` | 累计与双方贡献统计 |

> **只记正向，不记欠债**。这是产品底线：不做"谁欠谁"，`delta` 永远为正。

## 2. 接口契约

| 方法 | 路径 | 入参 | 出参 | 错误码 |
|---|---|---|---|---|
| GET | `/api/love/summary` | — | `total`, `mine`, `partner`, `recent[]` | 1002 |

出参示例：

```json
{
  "total": 42,
  "mine": 20,
  "partner": 22,
  "recent": [{ "delta": 1, "reason": "带饭完成", "createdAt": "2026-10-27 12:30" }]
}
```

> 爱心值也随 `GET /api/couple/info` 返回（关系卡要显示），两个接口共用同一个统计方法 `LoveValueService.summary(coupleId)`。

## 3. 实现

### 3.1 写入（唯一入口）

```java
@Transactional
public void award(Long coupleId, Long userId, Long planId) {
    try {
        loveValueMapper.insert(coupleId, userId, planId, 1, "带饭完成");
    } catch (DuplicateKeyException e) {
        // uk_love_value_plan_user 拦截 = 已经加过，幂等成功
    }
}
```

**三条铁律**：

1. **不做「先查再插」**。并发下必然漏判，交给唯一索引（D7）。
2. **只 catch `DuplicateKeyException`**，不能笼统 catch `Exception`——否则真出错也被当成功。
3. **调用方先改状态再调本方法**（见 `../20-约定/后端.md §3.5`），保证"状态成功才加分"。

### 3.2 统计

```sql
-- 双方各自累计 + 总计
SELECT user_id, SUM(delta) AS total
FROM love_value
WHERE couple_id = ?
GROUP BY user_id;
```

- **不做冗余计数列**。两人一年几百条，`SUM` 无压力；加计数列会引入双写不一致。
- 单 couple 流水破万时再考虑加计数字段（见 `../00-全局约定.md §6`）。

### 3.3 触发点

| 来源 | 说明 |
|---|---|
| 手动完成 `POST /api/plan/{id}/complete` | `status 3→4` 成功后加分 |
| 自动完成 `AutoCompleteJob` | `status 3→4` 成功后加分，**走同一条 `award` 逻辑** |
| 取消 / 过期 / 撤回 | **不加分**（非终态成功不算完成） |

## 5. 验收要点

对照 `openspec/changes/bootstrap-mvp/specs/love-value/spec.md`：

- [ ] 完成约定后带饭方 +1
- [ ] 重复点「完成」不重复加分（第二次状态更新 0 行）
- [ ] 并发点「完成」只加一次（`uk_love_value_plan_user` 兜底）
- [ ] 自动完成（超 24h）同样加分，且与手动完成结果一致
- [ ] 取消 / 过期 / 撤回**不加分**
- [ ] `GET /api/love/summary` 的 `mine + partner == total`

## 6. 易错点

| 坑 | 说明 |
|---|---|
| 先查后插 | 并发必漏判。**只靠 `uk_love_value_plan_user`** |
| catch `Exception` | 真故障被当成功，静默丢分。**只 catch `DuplicateKeyException`** |
| 用 `UPDATE ... SET balance = balance + 1` | 本项目是流水表，没有 `balance` 列。加余额列就要处理双写 |
| 取消也加分 | 只有 `status 3→4` 算完成，取消/过期不算 |
