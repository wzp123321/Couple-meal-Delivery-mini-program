# 50 通知 · 前端

> **OpenSpec**：`notifications` · **里程碑** M4
> **页面**：`pages/message`（Tab3）+ 全局 Tab 角标
> **前置必读**：`../00-全局约定.md`、`../前端-00-基础设施.md`（未读数同步在 §5.3）
> **接口契约**：见 `后端.md §2`
> **后端对应**：`后端.md`
> **MVP 范围**：仅站内红点/角标，不做微信订阅消息（二期）

---

## 1. 页面 → 接口

| 位置 | 调用 | 时机 |
|---|---|---|
| Tab3 角标 | `GET /api/msg/unread` | `onShow` / 动作成功后 / 回到前台 |
| `message` | `GET /api/msg/list` | 进页 / 下拉刷新 / 触底加载 |
| `message` | `POST /api/msg/read` | 进页时先本地置 0，再异步调 |

---

## 2. 未读数同步

完整规则见 `../前端-00-基础设施.md §5.3`（store + Tab 角标），本节只补页面侧要点：

| 时机 | 要点 |
|---|---|
| 进消息中心 | **先本地置 0** 消除角标，再异步调 `/api/msg/read`（避免角标滞后） |
| 列表项 | 未读项左侧带小圆点；已读项无 |
| 空态 | `empty-state`「还没有消息，等 TA 来找你」 |

---

## 3. 消息中心页（`pages/message`）

- 下拉刷新 + 触底分页（`pageNo/pageSize`）。
- 点消息**跳转到对应约定详情**（`plan_id` 非空时）：
  - type 1/2/3 → `pages/plan-detail`
  - type 6 → `pages/plan-detail` 并自动打开打卡详情区
  - type 5 → `pages/today`
- 跳转后**不标单条已读**（本模块只支持全部已读）。

---

## 4. 验收要点

对照 `openspec/changes/bootstrap-mvp/specs/notifications/spec.md`：

- [ ] 对方动作后，Tab 角标在下次 `onShow` 或轮询点更新
- [ ] 进消息中心后未读归零，Tab 角标消失且不再回弹
- [ ] 未读项有小圆点，已读项无
- [ ] 点击消息跳到正确页面；type 6 自动展开打卡区
- [ ] 解绑后消息列表不再出现上一段关系的内容

---

## 5. 易错点

| 坑 | 说明 |
|---|---|
| 先调接口再清角标 | 网络慢时角标滞后，用户以为没清掉。**先本地置 0** |
| 点击消息后单独标已读 | 本模块只有「全部已读」接口，单条操作会让前端状态与服务端不符 |
| 角标只在进页时取 | 回前台/切 Tab 都要 `onShow` 重取，否则一直显示旧数字 |
