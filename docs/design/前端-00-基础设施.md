# 前端 · 基础设施

> **读者**：所有前端任务（必读）。后端任务不需要读本文。
> **定位**：跨页面共用的工程结构、请求层、状态管理、样式、组件、错误码处理。**页面专属逻辑一律在各模块文档**。
> **技术栈**：**uni-app + Vue3 + Vite + TypeScript**，编译目标**仅微信小程序**。

## 1. 设计决策（F1–F9）

| 编号 | 决策点 | 选择 | 理由 | 代价 |
|---|---|---|---|---|
| F1 | 框架 | **uni-app（Vue3 + Vite + TS）** | 组件密度高：7 个跨页组件 + 9 个弹层靠 slot 传内容，原生 `properties` / `triggerEvent` 表达力明显弱于 `props` / `emit` / `slot`；打卡上传是有状态 UI，Vue 响应式比手动 `setData` 省一半代码 | 多一层编译；微信新 API 需等 uni-app 适配 |
| F2 | Vue 版本 | **只锁 Vue3**，不混用 Vue2 | Vue2 版 uni-app 走 webpack 且已 EOL；Vue3 版走 Vite，冷启与热更快 | 网上老教程多为 Vue2 写法（`new Vue`、`$on`），需甄别 |
| F3 | 状态管理 | **不引 Pinia**，`reactive` 单模块 | 全局态只有 3 类，Vue3 的 `reactive` 自带响应式，**不需要订阅/退订**；Pinia 的 devtools / 插件 / SSR 收益这里全为零 | 无时间旅行调试，无模块自动拆分 |
| F4 | 请求层 | `utils/request.ts` 封装 `uni.request` | 统一 token 注入、错误码分流、1001 静默重登 | — |
| F5 | 样式 | `uni.scss` 尺寸变量 + `rpx` + page 级 CSS 变量（颜色） | 颜色走 CSS 变量才能运行时换肤，SCSS 变量是编译期的不支持 | CSS 变量需基础库 2.11+ |
| F6 | 组件化 | 7 个 `.vue` 单文件组件 | 3 个以上页面复用的才抽 | — |
| F7 | 图片上传 | `uni.chooseMedia` → 压缩 → **逐张 `uni.uploadFile` + 单张重试** | PRD §12.7 要求单张失败不整单重来 | 上传状态机比批量复杂 |
| F8 | 本地缓存 | `uni.setStorageSync` 带 `schemaVersion`，登录态变更加版本号失效 | 换账号后旧缓存必须清 | 需在登录/解绑时主动清 |
| F9 | 分包 | MVP **不分包**，`pages.json` 预留 `subPackages` 空数组 | 13 页预估主包 < 1.5MB | 后续加大图预览再拆 |

> **框架选型的反转记录**：初版（2026-10-26）选原生小程序，理由是「页面少、无多端需求、包体最小」。2026-10-27 改为 uni-app，触发因素是**组件密度重估**——`bottom-sheet` 一个容器要承载 9 个弹层的内容，原生只能靠 slot 传 WXML，跨页组件回调还得 `triggerEvent` 逐层抛，而 Vue 的 `slot` + `emit` 是现成的。多端能力是顺带收益，不是主因。

## 2. 微信独有能力：条件编译

这是 uni-app 方案**唯一需要提前验证的风险点**。跨端 API 直接调，微信专有标签用条件编译包住。

| 能力 | 用途 | 写法 |
|---|---|---|
| `open-type="chooseAvatar"` | 选头像 | **微信专有**，条件编译 |
| `type="nickname"` | 昵称输入（`getUserProfile` 已废弃） | **微信专有**，条件编译 |
| `uni.login` | 换 code | 跨端 API |
| `uni.chooseMedia` | 打卡拍照 | 跨端 API |
| `uni.uploadFile` | 单张上传 | 跨端 API |
| `uni.setTabBarBadge` | 未读角标 | 跨端 API |

```vue
<!-- 设置页：头像昵称，微信专有能力包在条件编译里 -->
<!-- #ifdef MP-WEIXIN -->
<button class="avatar-btn" open-type="chooseAvatar" @chooseavatar="onChooseAvatar">
  <image class="avatar" :src="form.avatarUrl || defaultAvatar" mode="aspectFill" />
</button>
<input class="nickname" type="nickname" :value="form.nickname" @blur="onNicknameBlur" />
<!-- #endif -->

<!-- #ifndef MP-WEIXIN -->
<image class="avatar" :src="form.avatarUrl || defaultAvatar" mode="aspectFill" />
<!-- #endif -->
```

**三个易错点**

1. `@chooseavatar` 回传的 `e.detail.avatarUrl` 是**临时路径**（`http://tmp/...`），必须上传换成永久 URL 才能存库，直接存临时路径必然失效
2. `type="nickname"` 的值在 `blur` 时才可靠——键盘右上角「完成」不保证触发 `input` 事件
3. 条件编译注释必须**顶格**写成 `<!-- #ifdef MP-WEIXIN -->`，缩进会失效

**M0 必须实测这四项**（`chooseAvatar` / `type="nickname"` / `uni.login` / `uni.chooseMedia`）。前两项若 uni-app 透传有问题，就用上面的条件编译原生标签绕过，可行但要早验证。

## 4. 请求层

### 4.1 封装

```ts
// src/utils/request.ts
import { getToken, relogin } from './auth'
import { toast } from './toast'

const BASE = import.meta.env.VITE_API_BASE
const inflight = new Map<string, Promise<unknown>>()

interface Options {
  url: string
  method?: 'GET' | 'POST' | 'PUT' | 'DELETE'
  data?: Record<string, unknown>
  auth?: boolean
  silent?: boolean
  _retried?: boolean
}

export function request<T = unknown>(opt: Options): Promise<T> {
  const { url, method = 'GET', data, auth = true, silent = false, _retried = false } = opt
  const key = method + url + JSON.stringify(data || {})
  if (inflight.has(key)) return inflight.get(key) as Promise<T>

  const p = new Promise<T>((resolve, reject) => {
    const header: Record<string, string> = { 'content-type': 'application/json' }
    if (auth) header.Authorization = 'Bearer ' + getToken()

    uni.request({
      url: BASE + url,
      method,
      data,
      header,
      success(res) {
        const body = res.data as { code: number; msg?: string; data?: T }
        if (body.code === 0) return resolve(body.data as T)

        if (body.code === 1001 && !_retried && auth) {
          return relogin()
            .then(() => request<T>({ ...opt, _retried: true }))
            .then(resolve)
            .catch(reject)
        }
        if (body.code === 1002) {
          uni.reLaunch({ url: '/pages/pair/index' })
          return reject(body)
        }
        if (!silent) toast(body.msg || '出了点小状况')
        reject(body)
      },
      fail(err) {
        if (!silent) toast('网络不太顺，重试一下？')
        reject(err)
      },
    })
  }).finally(() => setTimeout(() => inflight.delete(key), 800))

  inflight.set(key, p)
  return p
}
```

**三条规则**

1. **文案只信后端**：`toast(body.msg)`，前端不维护第二份错误文案（后端 `00-全局约定.md §4` 已把文案写进 `ErrorCode`）。
2. **1001 只重放一次**：`_retried` 标记防死循环。
3. **写接口不静默**：只有轮询类和角标类请求用 `silent: true`。

### 4.2 上传接口

`uni.uploadFile` 是独立链路，不走 `request`，封装在 `utils/upload.ts`，同样注入 token、单独解析返回。
上传的具体状态机见 `60-打卡/前端.md §2`。

> `uni.uploadFile` 返回的 `res.data` 是**字符串**，必须 `JSON.parse` 后再判 `code`，直接当对象用会拿到 undefined。

上传接口返回 `{ url, thumbUrl }` 两档地址：**列表/网格用 `thumbUrl`，大图预览才用 `url`**。
前端选图时按 `count: 2 - 已选` 限制，并串行上传（同一时刻只 1 个请求），细节见 `60-打卡/前端.md §2`。

**两类上传，共用 `upload.ts` 但要分开入口**：

| 入口 | 接口 | 返回 | 调用方 |
|---|---|---|---|
| `uploadCheckin(files[])` | `/api/checkin/upload` | `{ url, thumbUrl }` | 打卡弹层（串行队列 + 单张重试） |
| `uploadAvatar(file)` | `/api/user/avatar` | `{ avatar }` | 设置页换头像（单张，不生成缩略图） |

头像不要复用打卡接口——打卡接口会生成 320 缩略图并走 `mediaCheckAsync` 异步队列，头像用不上，而且审核结果是同步返回的。

## 5. 状态管理

### 5.1 边界

| 类别 | 存哪 | 说明 |
|---|---|---|
| 登录态（token / userId） | storage + `appState` | 冷启动要能恢复，必须落盘 |
| 关系信息（coupleId / 昵称 / 在一起天数 / 爱心值） | 仅 `appState` | **不落盘**，每次冷启动重取，避免解绑后仍显示旧关系 |
| 未读数 | 仅 `appState` | 同步到 tabBar 角标 |
| 页面数据（今日约定、菜单列表） | 页面 `ref` | 不上升为全局状态 |
| 草稿（发起页输入） | storage | 按 `draft:plan-create` 键存 |

**铁律：服务端状态一律不本地臆造。** 任何写操作成功后，重新拉取对应读接口，不在前端手改 `status`。

### 5.2 实现

```ts
// src/stores/app.ts
import { reactive } from 'vue'

export interface Relation {
  coupleId: number
  partnerNickname: string
  togetherDays: number
  myLove: number
  partnerLove: number
}

export const appState = reactive<{
  user: { userId: number; nickname: string; avatar: string } | null
  relation: Relation | null
  unread: number
}>({
  user: null,
  relation: null,
  unread: 0,
})
```

页面用法（**不需要订阅，也不需要退订**）：

```vue
<script setup lang="ts">
import { appState } from '@/stores/app'
</script>

<template>
  <view class="badge" v-if="appState.unread > 0">
    {{ appState.unread > 99 ? '99+' : appState.unread }}
  </view>
</template>
```

**三条约束**

1. **不要解构**：`const { relation } = appState` 会丢失响应式，必须用 `appState.relation` 访问
2. **不要整体替换**：`appState = {...}` 会断开 reactive 引用，只能 `Object.assign(appState, patch)`
3. **只有三类全局态**，页面私有数据一律用 `ref` 留在页面内，别往 store 塞

### 5.3 未读数同步

| 时机 | 动作 |
|---|---|
| 冷启动 / 切前台 | `GET /api/msg/unread` → `appState.unread = n` |
| 收到通知类操作后（认领、送达、完成） | 直接 `+1` 并同步角标 |
| 进入消息中心 | 本地置 0 + 调 `POST /api/msg/read` |
| 角标渲染 | `>99` → `99+`，`=0` → `uni.removeTabBarBadge` |

### 5.4 路由门控

原方案用 `behaviors/pageAuth.js`，uni-app 改为**全局路由拦截**，一处配置、页面不各写一遍：

```ts
// src/utils/guard.ts
import { getToken } from './auth'

const WHITE_LIST = ['/pages/login/index', '/pages/pair/index']

export function setupGuard() {
  const check = (url: string) => {
    if (getToken()) return true
    if (WHITE_LIST.some((w) => url.startsWith(w))) return true
    uni.reLaunch({ url: '/pages/login/index' })
    return false
  }
  ;(['navigateTo', 'redirectTo', 'reLaunch', 'switchTab'] as const).forEach((api) =>
    uni.addInterceptor(api, { invoke: (args) => check(args.url) })
  )
}
```

> 在 `App.vue` 的 `onLaunch` 里调用 `setupGuard()`。

## 9. 弱网与本地草稿

| 场景 | 处理 |
|---|---|
| 页面无网络 | 顶部细条「网络断开，正在用上次的数据」，读缓存展示 |
| 提交超时 | 保留全部输入 + L1「发送失败，点此重试」 |
| 图片单张失败 | 单张重试，不整单重来 |
| 切后台回来 | 当前页 `onShow` 重取一次关键数据（今日约定、未读数） |
| 重复点击提交 | 请求层 800ms 去重 + 按钮 `loading` 态 |

## 10. 页面生命周期

uni-app 页面用 Vue3 组合式生命周期，**不是** `onLoad` 挂在 `export default` 上：

```vue
<script setup lang="ts">
import { ref } from 'vue'
import { onLoad, onShow, onUnload } from '@dcloudio/uni-app'

const plan = ref<Plan | null>(null)

onLoad((query) => { /* 只触发一次，拿路由参数 */ })
onShow(() => { /* 每次显示都触发，用于重取数据 */ })
onUnload(() => { /* 清理定时器、取消上传 */ })
</script>
```

| 场景 | 用哪个 |
|---|---|
| 拿路由参数、首次取数 | `onLoad` |
| 切前台 / 返回本页后刷新 | `onShow` |
| 清定时器 / 取消未完成上传 | `onUnload` |

> 常见错误：把取数逻辑写在 `onLoad` 里，从详情页返回列表时数据不刷新。列表页的重取要放 `onShow`。

## 12. 已知取舍（前端全局）

| 取舍 | 说明 | 何时该改 |
|---|---|---|
| 只用微信小程序端 | `manifest.json` 只配 `mp-weixin`，不花精力适配 H5 / App | 真要出 App 做本地通知时再开 |
| 不引 UI 组件库 | 只有 13 页，手写样式比引 uView 更贴合奶油风、包体更小 | 页面破 25 个再考虑 |
| 不引 Pinia | 3 类全局态，`reactive` 足够 | 状态破 8 类或出现深层嵌套再引 |
| 不做本地乐观更新 | 一律重取，状态永远以后端为准 | 弱网体验被投诉严重时再对个别动作做乐观更新 |
| 不分包 | 主包预估 < 1.5MB | 加视频预览 / 大图列表后必须拆 |
| 头像昵称不强制 | 登录只拿 code，昵称头像后补 | 若产品要求首次必填，改为登录后强制跳设置页 |
