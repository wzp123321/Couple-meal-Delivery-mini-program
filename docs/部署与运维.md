# 部署与运维

> **读者**：负责把服务跑起来、以及日后出问题时排查的人（初期就是你自己）。
> **定位**：从空服务器到线上可用的完整步骤 + 日常运维。**产品与接口细节不在本文**，见 `产品需求文档.md` 与 `design/`。
> **前置**：域名已备案、HTTPS 证书已申请（小程序 `request` / `uploadFile` 合法域名只认备案过的 HTTPS 域名）。

## 1. 服务器规格

**结论：一台 2 核 4G / 60GB SSD / 5Mbps 轻量应用服务器，MySQL 与后端同机。**

这个项目的并发天生极小（固定 2 人 × 每个工作日 1 条约定），瓶颈只有图片带宽。

### 1.1 内存

| 进程 | 常驻 | 说明 |
|---|---|---|
| Spring Boot 3.4（`-Xmx512m`） | 400–550MB | 单体 + MyBatis-Plus + 4 个 `@Scheduled` Job，无中间件 |
| MySQL 8.0（buffer pool 256M） | 600–700MB | 数据量一年才几百 MB |
| Nginx | 10–20MB | 反代 443→8080 + `/upload/` 静态映射 |
| OS + JDK | 250–300MB | |
| **合计** | **约 1.3–1.6GB** | |

4G 的价值不在 CPU，而是**给图片留 1.5GB 页缓存**。2G 不 OOM 但紧（页缓存不足，相册会明显变慢）；1C2G 只适合自己两人用，需调小 JVM 与 buffer pool 并开 swap。

### 1.2 磁盘

| 项 | 占用 |
|---|---|
| 系统 + JDK 21 + MySQL 8 | 3–5GB |
| 应用 jar | 50–80MB |
| 打卡图片 | 原图 ≤500KB + 缩略图 ≤60KB，两人一年 260 顿 ≈ **150–300MB/年** |
| 头像 | 每人一张 ≤100KB，可忽略 |
| 应用日志 | **必须按天滚动 + 保留 14 天**，否则开 SQL 日志时 20–50MB/天会吃满盘 |
| MySQL binlog | 单机无主从，`binlog_expire_logs_seconds` 设 3 天 |
| 本地备份 | 图片量的 1 倍（见 §6） |

40GB 能撑 1–2 年，60GB 更省心。**磁盘事故基本都不是容量不够，而是日志没轮转。**

### 1.3 带宽

5Mbps ≈ 640KB/s。相册一屏 10 张缩略图（每张 ≤60KB）≈ 600KB，**1 秒内出图**——这正是加缩略图档的原因，直接用 1080 原图一屏要 4MB、6–8 秒。

### 1.4 三档对照

| 档 | 适用 | 配置 | 年费参考（2026-10） |
|---|---|---|---|
| 够用 | 只自己两人 | 1核2G / 40G / 3–4M（需调参 + swap） | 活动价约 ¥99 |
| **推荐** | 自己 + 几个朋友 | **2核4G / 60–70G / 5–6M** | 活动价 ¥188–199，日常价约 ¥1000 |
| 宽裕 | 几十对情侣 | 4核8G / 100G / 8M + 图片转 COS | 活动价 ¥450 起 |

选**轻量应用服务器**即可，不需要 CVM 的弹性能力。

## 2. 系统初始化

```bash
# 时区：必须是东八区。定时任务 cron 全部按北京时间配置，
# 主机时区错 8 小时，超时归档与打卡窗口会整体失效（见 §8 故障表）
timedatectl set-timezone Asia/Shanghai
timedatectl set-ntp true
timedatectl                     # 确认 Time zone = Asia/Shanghai，NTP synchronized = yes

# 目录
mkdir -p /data/upload/{avatar} /data/backup /opt/couple-meal
useradd -r -s /sbin/nologin couplemeal
chown -R couplemeal:couplemeal /data/upload /opt/couple-meal
chmod 755 /data/upload          # Nginx worker 要能读；不要给写权限

# JDK 21（Spring Boot 3.4 要求 17+）
apt install -y openjdk-21-jre-headless
java -version
```

## 3. MySQL 8.0

**必须是 8.0，不能用 5.7**——`db/schema.sql` 用的 `utf8mb4_0900_ai_ci` 是 8.0 才有的 collation，5.7 直接建表失败。

```ini
# /etc/mysql/mysql.conf.d/mysqld.cnf
[mysqld]
character-set-server        = utf8mb4
collation-server            = utf8mb4_0900_ai_ci
default-time-zone           = '+08:00'
innodb_buffer_pool_size     = 256M
innodb_log_file_size        = 128M
max_connections             = 100
binlog_expire_logs_seconds  = 259200    # 3 天，单机无主从
slow_query_log              = 1
long_query_time             = 1
```

```bash
# 建库建账号
mysql -uroot -p <<'SQL'
CREATE DATABASE IF NOT EXISTS couple_meal
  DEFAULT CHARACTER SET utf8mb4 COLLATE utf8mb4_0900_ai_ci;
CREATE USER IF NOT EXISTS 'couplemeal'@'127.0.0.1' IDENTIFIED BY '换成强密码';
GRANT SELECT, INSERT, UPDATE, DELETE ON couple_meal.* TO 'couplemeal'@'127.0.0.1';
-- 备份账号只需读
CREATE USER IF NOT EXISTS 'backup'@'localhost' IDENTIFIED BY '另一个强密码';
GRANT SELECT, LOCK TABLES, SHOW VIEW, EVENT, TRIGGER ON couple_meal.* TO 'backup'@'localhost';
FLUSH PRIVILEGES;
SQL

# 建表
mysql -ucouplemeal -p couple_meal < /opt/couple-meal/db/schema.sql
mysql -ucouplemeal -p -e "SELECT COUNT(*) FROM information_schema.tables WHERE table_schema='couple_meal';"
# 期望 12
```

> 应用账号**不给 DDL 权限**：建表走发布流程，运行时只读写数据。
> 与 `00-全局约定.md §5` 一致，`spring.datasource.url` 里带 `serverTimezone=Asia/Shanghai`。

## 4. 后端部署

### 4.1 构建产物

```bash
# 本地构建（不要在服务器上装 Maven）
mvn -DskipTests clean package
scp target/couple-meal.jar root@服务器:/opt/couple-meal/app.jar
```

### 4.2 systemd

```ini
# /etc/systemd/system/couple-meal.service
[Unit]
Description=Couple Meal API
After=network.target mysql.service
Wants=mysql.service

[Service]
Type=simple
User=couplemeal
WorkingDirectory=/opt/couple-meal
Environment="TZ=Asia/Shanghai"
Environment="JAVA_TOOL_OPTIONS=-Xms256m -Xmx512m -XX:+UseG1GC -XX:+HeapDumpOnOutOfMemoryError -XX:HeapDumpPath=/opt/couple-meal/dump"
Environment="SPRING_PROFILES_ACTIVE=prod"
# 密钥只走环境变量，禁止写进 jar 或配置文件
EnvironmentFile=/opt/couple-meal/.env
ExecStart=/usr/bin/java -jar /opt/couple-meal/app.jar
Restart=always
RestartSec=5
StandardOutput=append:/data/logs/app.log
StandardError=append:/data/logs/app.err.log

# 只监听回环，对外由 Nginx 承接
# 在 application-prod.yml 配 server.address=127.0.0.1、server.port=8080
[Install]
WantedBy=multi-user.target
```

```ini
# /opt/couple-meal/.env   （chmod 600，属主 couplemeal）
JWT_SECRET=至少32位随机串
WX_APPID=wx...
WX_SECRET=...
MYSQL_PASSWORD=...
```

```bash
mkdir -p /data/logs && chown couplemeal:couplemeal /data/logs
systemctl daemon-reload && systemctl enable --now couple-meal
systemctl status couple-meal
curl -s http://127.0.0.1:8080/api/health   # 若有健康检查端点；没有就 curl 任意免鉴权接口看返回体
```

### 4.3 应用日志轮转

`logback-spring.xml` 里配按天滚动 + 保留 14 天 + 总量上限：

```xml
<appender name="FILE" class="ch.qos.logback.core.rolling.RollingFileAppender">
  <file>/data/logs/couple-meal.log</file>
  <rollingPolicy class="ch.qos.logback.core.rolling.SizeAndTimeBasedRollingPolicy">
    <fileNamePattern>/data/logs/couple-meal.%d{yyyy-MM-dd}.%i.log.gz</fileNamePattern>
    <maxFileSize>50MB</maxFileSize>
    <maxHistory>14</maxHistory>
    <totalSizeCap>2GB</totalSizeCap>
  </rollingPolicy>
</appender>
```

线上的 `stdout` 用 systemd 的重定向接管，`logrotate` 兜底（`/etc/logrotate.d/couple-meal`，`daily` + `rotate 14` + `compress`）。

> **生产 profile 关闭 SQL 日志**（`logging.level.xxx.mapper=info`）。开 `debug` 打全量 SQL，一天几十 MB，是磁盘被打满的头号原因。

## 5. Nginx

```nginx
# /etc/nginx/conf.d/couple-meal.conf
server {
    listen 80;
    server_name 你的域名;
    return 301 https://$host$request_uri;
}

server {
    listen 443 ssl http2;
    server_name 你的域名;

    ssl_certificate     /etc/letsencrypt/live/你的域名/fullchain.pem;
    ssl_certificate_key /etc/letsencrypt/live/你的域名/privkey.pem;
    ssl_protocols       TLSv1.2 TLSv1.3;

    # 打卡原图上限 10MB，留余量；默认 1MB 会让上传直接 413
    client_max_body_size 12m;

    # 接口反代
    location /api/ {
        proxy_pass         http://127.0.0.1:8080;
        proxy_set_header   Host              $host;
        proxy_set_header   X-Real-IP         $remote_addr;
        proxy_set_header   X-Forwarded-For   $proxy_add_x_forwarded_for;
        proxy_set_header   X-Forwarded-Proto $scheme;
        proxy_read_timeout 60s;
    }

    # 图片静态映射：/upload/xxx.jpg → /data/upload/xxx.jpg
    location /upload/ {
        alias /data/upload/;
        autoindex off;                      # 禁目录列表
        add_header Cache-Control "public, max-age=31536000, immutable";
        add_header X-Content-Type-Options nosniff;
        # 文件名是 uuid / userId+时间戳，内容不会变，可长缓存
    }

    access_log /var/log/nginx/couple-meal.access.log;
    error_log  /var/log/nginx/couple-meal.error.log warn;
}
```

要点：

- **8080 只监听 `127.0.0.1`**，不要把后端端口开到公网（`server.address=127.0.0.1`）。
- `location /upload/` 用 `alias` 而不是 `root`，否则路径会多一层 `upload/`。
- 文件名唯一（打卡 `{uuid}.jpg`、头像 `{userId}_{ts}.jpg`），所以可以 `immutable` 长缓存；换头像不会命中旧缓存。
- Nginx worker 需要对 `/data/upload` 有**读**权限即可，不要给写权限。

## 6. 备份与恢复

PRD §13 风险 18 的落地：**数据库 + 图片每天备份，保留 30 天**。恋爱记录和照片不可再生，备份不是可选项。

```bash
#!/bin/bash
# /opt/couple-meal/backup.sh   chmod 700，属主 couplemeal
set -euo pipefail
DAY=$(date +%F)
BK="/data/backup/$DAY"
mkdir -p "$BK"

# 一致性备份：--single-transaction 不锁表
mysqldump --single-transaction --quick --routines --triggers \
  -ubackup -p"$MYSQL_BACKUP_PWD" couple_meal | gzip > "$BK/db.sql.gz"

# 图片（含头像与打卡图）
tar czf "$BK/upload.tar.gz" -C /data upload

# 只保留 30 天
find /data/backup -mindepth 1 -maxdepth 1 -type d -mtime +30 -exec rm -rf {} +

echo "[$(date '+%F %T')] backup ok: $(du -sh "$BK" | cut -f1)"
```

```cron
# crontab -e（couplemeal 用户）
30 3 * * * /opt/couple-meal/backup.sh >> /data/logs/backup.log 2>&1
```

**异地**：云厂商的对象存储挂一个同步任务（如 `rclone sync /data/backup cos:mybucket/couple-meal`，每日一次）。同机备份只防误删，不防整机故障。

**每季度演练一次恢复**，没演练过的备份等于没有备份：

```bash
gunzip < /data/backup/2026-10-27/db.sql.gz | mysql -utest -p test_db
tar tzf /data/backup/2026-10-27/upload.tar.gz | head   # 确认能解开、文件数对得上
```

## 7. 上线检查清单

**服务端**

- [ ] `timedatectl` 显示 `Asia/Shanghai` + NTP 已同步
- [ ] MySQL 是 8.0，`SELECT @@collation_server` = `utf8mb4_0900_ai_ci`
- [ ] `schema.sql` 执行完 12 张表
- [ ] 8080 只监听 `127.0.0.1`（`ss -lntp | grep 8080`）
- [ ] 443 证书有效，`curl -I https://域名` 返回 200
- [ ] `/data/upload` 下文件可通过 `https://域名/upload/...` 访问
- [ ] 上传 8MB 图片不被 413 拦截
- [ ] 日志文件在滚动（隔天应出现 `.gz`）
- [ ] 备份 cron 已跑过一次，`/data/backup/` 下有当天目录
- [ ] 重启机器后服务自动拉起（`systemctl is-enabled couple-meal`）

**微信侧**

- [ ] 小程序后台配置合法域名：`request` / `uploadFile` / `downloadFile` **三类都要配**（只配 request 会导致上传和看图失败）
- [ ] 服务类目选「工具」或「生活服务」，**不要选「餐饮-外卖/点餐」**（会要求《食品经营许可证》）
- [ ] 隐私保护指引已填写（收集 openid / 昵称 / 头像 / 相册）
- [ ] 用户隐私保护指引开关（`__usePrivacyCheck__`）已开启
- [ ] 内容安全检测接口权限已开通（`imgSecCheck` / `msgSecCheck` / `mediaCheckAsync`）

## 8. 常见故障对照

| 现象 | 原因 | 处理 |
|---|---|---|
| 定时任务时间偏 8 小时、过期归档在下午跑 | 主机或 MySQL 时区错 | `timedatectl` + `default-time-zone='+08:00'`，两个都要对 |
| 建表报 `Unknown collation: utf8mb4_0900_ai_ci` | MySQL 是 5.7 | 升到 8.0，不要改 collation 迁就 |
| 上传接口 413 | Nginx `client_max_body_size` 太小 | 调到 `12m` |
| 图片 403 / 404 | Nginx 无 `/data/upload` 读权限，或 `alias` 写成了 `root` | `chmod 755 /data/upload`，检查 alias |
| 磁盘满 | 应用日志没轮转 / 开了 SQL debug 日志 | 查 `/data/logs` 与 binlog；配好 `maxHistory` + `totalSizeCap` |
| 换头像后仍显示旧图 | 库里存了 `http://tmp/` 临时路径，或文件名固定导致强缓存 | 见 `design/10-关系绑定/后端.md §3.6`（D16） |
| 头像上传返回 4003 | `imgSecCheck` 未通过 | 属正常业务拒绝，前端提示换一张 |
| 服务启动即退出 | 缺环境变量（`JWT_SECRET` / `WX_*`） | `journalctl -u couple-meal -n 100` |
| 注销后旧 token 还能用 | `AuthInterceptor` 没按 `uid` 回查 `user` | 见 `design/10-关系绑定/后端.md §3.5` |

## 9. 日常运维动作

| 频率 | 动作 |
|---|---|
| 每天 | 看 `backup.log` 有没有 `backup ok`；看磁盘 `df -h` |
| 每周 | `journalctl -u couple-meal --since "7 days ago" -p err` 扫一眼错误 |
| 每月 | 检查证书有效期（`certbot renew --dry-run`）；相册接口用真实数据看一眼缩略图是否生效 |
| 每季度 | 恢复演练（§6）；评估磁盘增长是否与预期一致 |
| 一年 | 续费服务器；升级 JDK / MySQL 小版本（先在本机验证再上） |
